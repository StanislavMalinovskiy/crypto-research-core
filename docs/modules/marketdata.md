# marketdata

- **Responsibility:** append-only raw provider observations now; provider adapters, normalization, swaps, tokens, observed prices, price snapshots, source/quality facts and stream-gap recovery in later approved changes.
- **Owned data:** the `marketdata` schema currently contains the ordinary unpartitioned `raw_chain_events` table; its identity is `(chain_id, transaction_value, event_locator, provider)`, whose textual columns use deterministic bytewise `C` collation, and it preserves observed block position/hash, source/observation/ingestion time, exact payload, qualified SHA-256 digest and parser version. The natural primary-key index is its only index; normalized facts, snapshots, fingerprints and operational state remain future objects introduced only with their owning changes.
- **Public API:** no raw-storage contract is exposed through `marketdata::api`; future synchronous, domain-neutral access to normalized data and immutable point-in-time price observations remains TBD.
- **Allowed dependencies:** `kernel::api`.
- **Published/consumed events:** high-volume swaps and ticks remain internal; low-frequency completed facts are TBD.
- **Invariants:** persist raw input before normalization; `raw_chain_events` is append-only and uses exact CAIP-2 network identity plus transaction value, canonical event locator and provider; key equality is deterministic and bytewise rather than inherited from the database default collation; `ingested_at`, finality and canonicality never participate in identity; raw identity components have matching Java/SQL UTF-8 byte budgets so accepted multibyte values remain safe for the composite PostgreSQL key; an equal retry preserves the first observation and ingestion times, while different immutable evidence for that identity fails without overwrite; payload digest is derived from exact UTF-8 bytes as `sha256:<lowercase-hex>`; authoritative times are truncated to PostgreSQL microseconds; normalized blockchain-event identity will omit provider while retaining it as lineage; a parser/version change cannot alter the locator of the same event; Solana slot/EVM block number is `BlockPosition`, never a misleading block-height field, and optional block hash is separate; V1 admits only stable-inclusion historical/finalized evidence by caller contract but does not verify finality; provisional ingestion requires an approved finality/reorg change; partitioning, surrogate IDs, BRIN and secondary indexes require a separate evidence-backed change that preserves global idempotency; other modules never read market-data tables directly.
- **Non-goals:** signal generation, wallet scoring, risk decisions, outcome valuation, friction rules, report aggregation and EVM implementation in MVP.
- **Main tests:** current tests cover validation, deterministic digest/time normalization, Flyway V1, exact unpartitioned PostgreSQL schema/constraints/indexes, synthetic EVM readback through the common model, Solana/Base and provider distinction, idempotent and conflicting retry behavior, first-ingestion preservation and concurrent submissions. Recorded provider fixtures, raw replay, gap recovery and price provenance arrive with their implementing changes.
