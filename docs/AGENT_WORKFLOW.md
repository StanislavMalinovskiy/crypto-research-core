# Работа с Codex-агентами

## Статус

Роли для этой схемы настроены в `.codex/agents/`, но процесс не запускается автоматически и не является обязательным для каждой задачи. Architect решает, когда создавать подагентов.

Настройки ролей: Architect — `gpt-5.6-sol/high`; Developer и Tester — `gpt-5.6-sol/medium`; Reviewer — `gpt-5.6-sol/high`; Researcher — `gpt-5.6-sol/medium`.

Все подагенты наследуют от основной сессии разрешения, MCP-серверы и skills. Их конфигурация не ограничивает доступные возможности. Одновременно могут работать до четырёх подагентов, не считая Architect.

## Роли

### Architect

- определяет цель, границы и ожидаемый результат изменения;
- сверяет решение с Roadmap, архитектурой, ADR и OpenSpec;
- передаёт согласованную задачу Developer;
- принимает итоговое решение после review.

### Developer

- реализует согласованный scope;
- обновляет код, тесты и связанную документацию;
- выполняет необходимые проверки;
- исправляет замечания, возвращённые после review.

### Tester

- проверяет реализованное поведение и воспроизводит ошибки;
- запускает подходящие unit, integration и architecture checks;
- при необходимости улучшает тестовое покрытие;
- возвращает результаты и оставшиеся риски.

### Reviewer

- независимо проверяет реализацию и результаты тестов;
- ищет ошибки в корректности, архитектуре, данных и миграциях;
- не расширяет scope задачи;
- выдаёт результат: `APPROVE`, `APPROVE WITH CHANGES` или `REQUEST CHANGES`.

### Researcher

- исследует код, документацию, протоколы и варианты реализации;
- проверяет изменяемые внешние факты по авторитетным источникам;
- отделяет подтверждённые сведения от предположений;
- возвращает краткие выводы и практические последствия.

## Рабочий цикл

```text
Architect
  |-- Researcher (при необходимости) --|
  |                                     v
  +------------------------------> Developer -> Tester -> Reviewer
                                         ^                    |
                                         |---- замечания ------|
  <---------------- итоговое решение --------------------------|
```

Architect создаёт только нужные для задачи роли. При замечаниях работа возвращается Developer, Tester повторяет необходимые проверки, а Reviewer оценивает исправленный результат. После одобрения Architect сверяет итог с исходной целью и передаёт его пользователю.

Полный цикл полезен для OpenSpec changes, изменений архитектуры, схемы данных и важной бизнес-логики. Небольшие правки могут выполняться одним агентом без запуска всех ролей.

Пользователь сохраняет финальное решение и отдельно определяет, когда применять этот процесс.
