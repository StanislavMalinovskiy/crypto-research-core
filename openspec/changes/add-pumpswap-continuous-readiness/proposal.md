## Why

The qualified bounded collector, fixed-v4 decoder and immutable operation store now exist, but application restart and repeated finite segments do not yet form one conservatively budgeted, resumable capture-to-derivation workload. Readiness must be proved locally before any separately authorized activation.

## What Changes

- Add a default-disabled, explicitly configured finite-segment coordinator in the existing marketdata workload.
- Bind every automatic and manual start in its enrolled provider allocation to one immutable deployment budget; reserve finite segment resources before provider work and retain reservations after crashes.
- Continue only after verified natural segment completion, with explicit boundary/restart gaps and no automatic restart after failure, owner stop or cumulative exhaustion.
- Derive committed raw evidence with the fixed verified decoder and existing V14 publication API in bounded resumable pages after each segment is sealed.
- Prove restart, fencing, budget, provenance and shutdown behavior using local synthetic transport/isolated PostgreSQL, including one several-minute wall-clock test.

## Capabilities

### New Capabilities

- `pumpswap-continuous-readiness`: disabled-default finite deployment orchestration, durable cumulative resource authority, explicit segment boundaries and resumable fixed-version derivation.

### Modified Capabilities

None in accepted main specs. The new wrapper narrowly supersedes the active collector's prohibition on another automatic launch only for an already-authorized, verified natural segment boundary inside the same frozen deployment allocation. It does not reopen the terminal collector session or modify legacy launch/recovery behavior; exact overlap and precedence are recorded in [design](design.md).

## Impact

Only marketdata launcher/settings/application/persistence and owning tests, one forward-only V15 migration, and explicitly bounded additive migration-list compatibility expectations. No dependency, framework, workload role, module edge, new endpoint, event registry or general job infrastructure. Existing V5/V13/V14 evidence, decoder economics and exact monitor contract remain unchanged.

Prior cumulative usage, reservations, UNKNOWN billing and immutable receipts remain intact.
