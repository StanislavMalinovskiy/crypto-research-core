## Decisions

1. **Separate public diagnostic, existing modules.** Add `MarketDataApi.pumpSwapChainTimeCandles(Request)` and ordinary-value `PumpSwapChainTimeCandles` records; add `SignalApi.diagnosePumpSwapNativePriceRise(Request)` and `PumpSwapNativePriceSignal` records. The existing signal implementation delegates to a small separate diagnostic use case; it does not invoke candidate transitions, risk or evaluation. Reuse marketdata's integrity-checked `PersistPumpSwapOperationsUseCase.find`, canonical source-membership checks and fingerprint conventions; use a new pure calculator rather than changing v1 observation-time metrics. Extract only bounded raw blockTime/index from already retained parents with duplicate-key rejection/digest/identity checks. No shared repository/cross-module SQL. Alternative: forcing accepted liquidity-spike/valuation would invent unavailable USD/risk inputs and expand admission; rejected.
2. **Independent coherent source read.** Marketdata owns REQUIRES_NEW/readOnly/REPEATABLE_READ10s plus existing bounded Jdbc reader; validate request before read and calculate afterwards. Signal validates first, calls that API once and calculates without an outer transaction. No new queries beyond the existing batch reader, writes, locks or provider work. This protects ambient-caller isolation and unchanged batch membership; no new persisted snapshot infrastructure.
3. **Two clocks, no backdating.** Keep explicit event range/E separate from knowledge K. Conservative per-operation knownAt=max(raw received/admitted/ingested, parent+operation+batch persistedAt); raw/source and derivation times remain separately reported. This is a conservative lower-risk observable availability rule, not full commit-time/decision-admission proof. K before batch publication yields unavailable knowledge/INSUFFICIENT, not historical usable prices. K after publication can show old pattern at K; label retrospective and historical-at-E availability unavailable if any relevant source first appeared after E. No implicit current clock/default old decision timestamps. Late-arriving/backfilled rows never alter old immutable batch results at a prior cutoff; a distinct batch/key/cutoff has distinct identity.
4. **Raw event time and ordering.** Integral raw blockTime→UTCInstant, validate sourceTime agreement. Null missing→counted exclusion; malformed/contradictory identity/digest/time→failure. Check signature→slot/index/time and slot/index→signature within the frozen source; no interpolation. Order exactly as delta, grouping by component tuples; numeric slot precedes provider-reported index/signature/paths. Missing index gets explicit presence ordering, never index0 or fake chronology. Open/close with fallback remain diagnostic deterministic endpoints; first signal refuses missing-index eligible members. Whole-batch validation precedes filtering so contradictory out-of-window source cannot be hidden. Independent provider-index accuracy and gaps remain unverified.
5. **Native exact arithmetic.** Only WSOL-quoted groups; prove quote mint and decimals9 through retained raw token-balance/mint metadata and the fixed v4 operation endpoint proof, not a mint-name/default guess. Base decimals also resolve to that existing raw-linked proof and agree across selected rows (0..255 existing source limits); Token-2022 ambiguity remains unpriced. Reuse reduced BigInteger rational/cross multiplication, sum raw units per group, exact SOL volume scale9/UNNECESSARY only for proven WSOL units. Formula `quoteRaw * 10^baseDecimals / (baseRaw * 10^quoteDecimals)` is SOL per human base-token unit, not quote/base atom ratio. Decimal-price display scale18/HALF_EVEN is presentation only; ratios are fingerprinted. OHLC is observed execution price, not spot reserves, USD, executable liquidity or fee-adjusted result. Missing decimals stay counted/unpriced, conflict rejects; no new fee aggregation.
6. **First diagnostic family.** `native-sol-price-rise-v1`: two adjacent300s bars ending explicitE, inclusive currentClose/priorClose>=105/100. Exact threshold, interval, minimum1priced operation/bar and insufficiency policy are engineering defaults versioned before looking at outcomes; not empirical optimum. Samegroup only; no crosspool combination/dust filter/wallet ranking. Missing bar/eligible time/knowledge/index/price→INSUFFICIENT; below-threshold adequate observations→NO_TRIGGER; threshold met→TRIGGER. Selected unpriced/missing-index rows or potentially relevant excluded unknown-time/future-knowledge rows force insufficiency. Gap absence/fees remain unbound/unknown even when threshold computable, so readiness always diagnostic-only. No positive trigger count acceptance; saved sparse data may return only insufficient/no-trigger.
7. **Bounded identity/report.** Inherit128tx/10000ops/64MB batch limits, one300s interval,1000requestbucket positions/10000populatedgroupbarrows/64MB output. Empty bars absent, never filled. All transaction statuses and operation inclusions/exclusions reconcile; include batch/decoder/storage/schema/canonical versions/pins, raw/revision refs, knownAt/E/K, native ratios/amounts, reasons and limitations in versioned length-prefixed SHA256. No system clock/generated timestamp/seed or accepted-signal ID.
