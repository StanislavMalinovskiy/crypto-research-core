## Decisions

1. **Owning API and exactly two reads.** Add `PumpSwapOperatorReport.Result pumpSwapOperatorReport(PumpSwapOperatorReport.Request request)`. API holder has immutable Request(UUID sessionId, PumpSwapPoolMetrics.Request metrics) and Result(formatVersion, normalized request, association, consistency, monitorStatus, metricsStatus, json, summary), ordinary Java values only. New composing use case injects the existing monitor and metrics readers plus pure formatter; validate request/session and reuse existing `PumpSwapPoolMetricsCalculator.normalize` before any reader call. Read monitor first, then metrics, at most once each, even if one is absent; a failing first read stops before the second. Do not inject MarketDataApi into its own delegate or introduce a repository/raw read. No composing transaction, executor/retry, new SQL or clock sample; each existing reader keeps its own owning transaction/deadline. Formatting occurs after both owned read transactions, though an ambient caller transaction may be resumed. Existing caller-private isolation/commit/rollback behavior remains unchanged. Null/invalid input rejects safely; component RuntimeException becomes constant `OPERATOR_REPORT_READ_FAILED` without exception text/cause in output; fatal JVM errors are not caught. Malformed requests never touch sources. Alternative third batch read would add work without establishing durable binding and is rejected.

2. **Independent provenance by construction.** Both request IDs are explicit, never chosen from latest capture/batch or compared heuristically. Association always REQUESTED_TOGETHER_UNVERIFIED, consistency INDEPENDENT_PANELS; fixed labels are also in summary. Preserve existing monitor observedAt, recorded lease/window/state/gaps and metrics normalized request/source/fingerprint exactly. No report-generated timestamp, aggregate fingerprint, denominator/coverage/completion comparison, subscription-count derivation or reconstruction of monitor status at metric cutoff. A report may pair unrelated existing evidence; it does not reject honest independent panels as a binding error or declare them linked. Absent components are explicit statuses/nulls, not errors or synthesized zero rows. A failed read is not absence and no partial success is returned. Component-level metrics fingerprint remains identical on repeated frozen input; complete report changes legitimately with monitor observation/state. Equal complete component values produce equal JSON/summary; this is packaging determinism, not immutable report persistence.

3. **Small fixed render schema with exact values.** JSON root fields are formatVersion, request, association, consistency, monitor(status,snapshot), metrics(status,result); present snapshot/result are complete existing public safe records, absence is null. No internal StoredBatch, capture replay/configuration/proof/raw/source payload or Throwable enters formatter. Use the installed Jackson baseline locally, without changing the global ObjectMapper or adding a module/dependency. Construct a typed allowlisted record/tree projection; normalize every integral JSON leaf to a canonical decimal string (including counters/slots/paths/intervals/fees/rational components), preserve booleans/nulls/UTC text, recursively sort object fields by unsigned UTF8 and retain source list order. Both renderings use the same two in-memory panels; never reread for summary. JSON strings use ordinary JSON escaping; summary input strings use escaped single-line text (JSON-quoted strings are sufficient), no ANSI/control injection. No numeric parsing through double, percentages, USD formatting or new native aggregates. Preserve metrics fingerprint as source identifier, not hash of changed serialization. Unknown schema values are not silently omitted.

4. **Finite render budget and summary.** Stream JSON through a bounded UTF8 byte sink capped at64000000 before materializing/publishing the returned string; cap escaped summary UTF8 at16384 bytes. Failure is constant `OPERATOR_REPORT_OUTPUT_LIMIT` for excess, `OPERATOR_REPORT_FORMAT_FAILED` for other rendering failures; no logging/file output/truncation. A valid maximum metrics result can still exceed the independent JSON packaging budget because endpoint refs/escaping add bytes: explicit rejection is intentional, not weakened metrics limits. Summary uses fixed English field labels/order, request IDs, association/consistency, distinct presence statuses; present monitor supplies observedAt/state/reason/lease/window/all counters, unresolved total/truncation/inconsistency plus activity/coverage/loss/billing labels. Label rpcHundredths as committed local measured usage and reservedHundredths as conservative reservation, not spend/invoice. Present metrics supplies its exact fingerprint/request window/cutoff/interval, full reconciliation and all status counts, populated candle/pool counts and interpretation/source limitations. No per-candle/per-reference human dump. Full JSON retains all source statuses/reasons, references/limitations and gap details; concise summary is explicitly a summary, not an alternative denominator. Escaped long reason/limitation may exceed summary ceiling and rejects without shortening source facts.
