## Decisions

1. **API and read boundary.** Add `Optional<PumpSwapPoolMetrics.Result> pumpSwapPoolMetrics(PumpSwapPoolMetrics.Request request)` to `MarketDataApi`; immutable nested records live in the new API holder. Request fields are exact batchKey, fromInclusive, toExclusive, observationCutoff and intervalSeconds. Validate key (`sha256:` plus64 lowercase hex), nulls, supported interval/alignment/order/work shape before calling the existing reader. `ReadPumpSwapPoolMetricsUseCase` uses an application-owned `TransactionTemplate` configured REQUIRES_NEW, readOnly, REPEATABLE_READ, timeout10 seconds only around `PersistPumpSwapOperationsUseCase.find`. Existing JdbcTemplate statements inherit the finite transaction deadline. No query loop, retry or new SQL is needed. After return the pure calculator runs outside that owned read transaction, without provider I/O. Ambient callers are suspended/resumed for reading, not committed/rolled back by this use case; no schema/secret access at startup. Unknown key is Optional.empty. Alternative arbitrary `StoredBatch` public input was rejected because it would create an untrusted result importer; new range SQL was rejected because the exact bounded reader already supplies the required source.

2. **Canonical sources, no silent selection.** Validate each canonical operation has exactly one revision across the complete batch before filtering; otherwise `METRICS_AMBIGUOUS_OPERATION_REVISION`. Join metadata to parents by exact transactionRevisionKey and operationRevisionKeys, not trader/provider/digest-only heuristics or zipped independently sorted lists. The verified wrapper/result operation metadata have matching manifest order; use explicit revision-parent membership and preserve exact references. Canonical keys keep chain/signature/full numeric path/leg, independently of pool/session/provider. Repeated store retries already resolve one row. Rejecting alternate revisions is intentionally conservative; explicit revision selection/merging can be a later approved capability. It never rewrites/rejects the existing storage capability itself.

3. **Closed observation-time buckets.** Use UTC epoch-aligned intervals60/300/3600 seconds; require whole-second aligned from/to and nonempty width of at most1000 intervals. Normalize cutoff to microseconds first, require toExclusive<=cutoff; original receivedAt alone assigns operations. Use exact Instant/integer arithmetic and reject unrepresentable bounds. These are supported display granularities/work bounds, not financial quality thresholds or chronology reconstruction. Group by component tuple chain/pool/baseMint/quoteMint/bucketStart; sort strings unsigned UTF-8 and instruction paths numeric prefix-first. Endpoint order and sparse-output rules are fixed in the spec. A chain slot or lexicographic signature tie does not prove on-chain chronology. No mutable monitor read participates in the fingerprint; inherited limitations and constant INCOMPLETE/UNKNOWN classifications prevent fabricated continuity when gap metadata is absent.

4. **Exact amounts and prices without rounding.** Sum BigInteger raw amounts, count supported buy/sell variants from the fixed v4 proof. Do not sum differing groups. Ratio is reduced positive BigInteger numerator/denominator after decimal powers0..255, with gcd normalization and exact cross multiplication. No BigDecimal rendering/rounded authority is needed for v1. Conflicting observed decimals within any included pool/mint group fail `METRICS_DECIMALS_CONFLICT`; missing decimals retain all volumes/counts with unpriced references/reasons. OHLC Optional is absent only when no operation qualifies; partial eligible coverage is explicitly counted. High/low ties take earliest price-eligible source; open/close reference first/last eligible source. Every endpoint carries operation/transaction revisions. Fee declarations, attributed flows and network fees remain source facts; no expense sum or allocation is introduced. Alternative spot/reserve/USD formulas are unsupported by these source proofs.

5. **Bounded result and fingerprint.** Calculator visits at most10000 operations and128 transactions; grouping emits at most10000 populated rows, the request contains at most1000 bucket positions, and canonical result encoding rejects above64MB before success. Output includes per-pool totals, populated candle rows, selected/outside operation revision references, missing-decimal reasons, all transaction revision/status/reason/receivedAt/window dispositions, batch/source versions/pins/limitations and the fixed interpretation labels from the spec; never raw payloads. Eligible+unpriced=selected, selected+outside=all operations, inside+outside=all transactions, buy+sell=selected. Use existing `CanonicalFingerprint` length-prefixed UTF-8 SHA-256 with domain/algorithm `pumpswap-pool-metrics-v1` and canonicalization `length-prefixed-v1`; include normalized request, exact batch key/result fingerprint/storage and decoder versions/pins, all ordered report fields/references and limitations. No current/generated timestamp participates. It is a report fingerprint, not an admissible dataset fingerprint. Processing an old observation window is HISTORICAL_DIAGNOSTIC: receivedAt<=cutoff does not mean derived revisions/quality were available at that historical decision time.
