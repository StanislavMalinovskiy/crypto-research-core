## Decisions

### Placement and explicit route

One signal-owned MVC controller uses injected public `MarketDataApi.captureMonitor(UUID)` and `SignalApi.diagnoseRetainedPumpSwapNativePriceRise(Request)`. No `@Transactional` in web classes; no private module imports. HTML/JS live beneath `classpath:signal/operator/`, NOT global static resources, and are served only by the enabled controller. No template/rendering framework or dependency; a generic dashboard/engine is unnecessary.

Routes: `GET /operator` and `GET /operator/operator.js`; `GET /operator/api/capture?session=<UUID>`; bodyless `POST /operator/api/diagnostic` with exact query fields `session,receivedFrom,receivedTo,eventFrom,eventTo,chain,pool,baseMint,quoteMint,eventEnd`. Instants are UTC ISO text; request maps to the existing retained request/exact Pool, with no caller K/D/version/source substitutions. Require exactly the allowed fields once each, query<=4096 UTF-8 bytes, each field<=256 bytes, valid UUID/instants/pool identity and inherited scope bounds before API calls; malformed/unknown/repeated fields reject400. POST with body/Transfer-Encoding rejects400 before reads. The HTML has independent explicit session-monitor and diagnostic forms, no default session/pool/window, no automatic call on load. Browser obtains values as strings, uses URLSearchParams and only user submit/refresh; buttons disable while each request runs.

Monitor calls once and returns MONITOR_PRESENT or MONITOR_ABSENT/null (404 is not fabricated zero). Diagnostic calls only the bridge once, no additional monitor/source/pool-discovery call or retry. Panels retain distinct observation times and `INDEPENDENT_PANELS`; requested same session is declared, not one atomic common snapshot. One adapter-wide nonblocking in-flight diagnostic permit,429 BUSY/no API call when occupied, released in finally including errors; no queue/new worker. Existing bridge4096-source/64MB/10s read and bounded calculations remain; one selected window is NOT a24h throughput/count promise.

### Fail-closed local security

Property `crypto.research.signal.operator-screen.enabled` absent/false means all four routes/resources absent404; no capture-default/application.yaml edits. Only the enabled controller validates startup: exact `server.address=127.0.0.1`; `server.forward-headers-strategy` absent or `none`; BOTH `crypto.research.marketdata.capture.enabled` and `.continuous-enabled` false. Other values fail safely before readiness; no imports of marketdata settings or launcher. This is a standalone local adapter, not a flag that may be enabled on the collecting process.

Every route checks original servlet local/remote address exactly127.0.0.1; rejects forwarded headers (`Forwarded` or any `X-Forwarded-*`), non-local Host (only literal127.0.0.1/localhost with optional valid port), cross-origin Origin when present, and `Sec-Fetch-Site: cross-site` before reads/resource response. JSON routes additionally require `X-Operator-Request: local-manual-v1`; POST and cross-origin preflight never gain CORS permission. Compare Origin against the actual http scheme/validated Host, never forwarded metadata. No public auth/session/cookie claim: trusted same-host/SSH-tunnel operators only; public/reverse-proxy exposure requires a separate security contract. Per-response no-store, nosniff, DENY framing/referrer no-referrer, and CSP `default-src 'none'; script-src 'self'; connect-src 'self'; style-src 'none'; img-src 'none'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'none'`. HTML has external same-origin JS, no inline script, HTML interpolation or active provider links.
