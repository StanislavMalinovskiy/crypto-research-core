Для создания системы, которая будет мониторить Solana/Pump.fun, Arbitrum и Base с использованием Virtual Threads и Structured Concurrency, вам потребуются определенные подписки и API доступы. Рассмотрим каждую сеть отдельно и оценим необходимые ресурсы.
## 1. Solana / Pump.fun
### Бесплатные опции:
- **Публичные RPC ноды Solana**:
	- `https://api.mainnet-beta.solana.com` (RPC)
	- `wss://api.mainnet-beta.solana.com` (WebSocket)
	- Ограничения: 100 запросов/10 секунд, могут быть периоды недоступности
### Платные опции:
- **Helius** (рекомендуется для продакшн):
	- Starter план: \$49/месяц (50 запросов/сек)
	- Pro план: \$99/месяц (100 запросов/сек)
	- Преимущества: стабильность, поддержка WebHooks, расширенная аналитика
- **QuickNode**:
	- Build & Run план: \$49/месяц (40M запросов/месяц)
	- Преимущества: множество дополнительных API точек
### Необходимый функционал:
- WebSocket-подписка на Pump.fun Program ID
- RPC-методы для получения деталей транзакций
- RPC-методы для получения данных о токенах
## 2. Arbitrum
### Бесплатные опции:
- **Public RPCs**:
	- `https://arb1.arbitrum.io/rpc` (HTTP)
	- Ограничения: до 20 запросов/сек, без гарантии стабильности
### Платные опции:
- **Alchemy**:
	- Growth план: \$49/месяц (25M вычислительных единиц)
	- Преимущества: высокая стабильность, WebSocket поддержка, архивный доступ
- **Infura**:
	- Core план: \$29.99/месяц (\~4M запросов/день)
	- Team план: \$99/месяц (\~9M запросов/день)
### Необходимый функционал:
- WebSocket подписка на события DEX контрактов
- RPC-методы для получения истории транзакций
- RPC-методы для чтения данных смарт-контрактов

## Архитектурные решения для эффективного использования API
1. **Уровни кэширования**:
	- Агрессивное кэширование неизменяемых данных (информация о токенах)
	- Кэширование цен с TTL \~30-60 сек
	- Кэширование ликвидности с TTL \~5-10 мин
2. **Стратегии rate limiting**:
	- Использование Resilience4j для ограничения частоты запросов
	- Экспоненциальный backoff при ошибках
	- Разные лимиты для разных методов API
3. **Приоритезация запросов**:
	- Высокий приоритет: необходимые для класса A обогащения
	- Средний приоритет: класс B обогащения
	- Низкий приоритет: класс C обогащения и исторические данные
4. **Fallback стратегии**:
	- Несколько провайдеров RPC для каждой сети
	- Переключение между ними при недоступности основного
	- Временное отключение неприоритетных функций при проблемах

## Заключение
Для эффективной работы с тремя блокчейнами (Solana, Arbitrum, Base) я рекомендую:
1. **Начать с Solana/Pump.fun на бесплатном API**, но быть готовым перейти на Helius (\$49/месяц) при первых признаках ограничений или нестабильности.
2. **Для Arbitrum и Base** сначала реализовать базовую поддержку на бесплатных RPC, с переходом на Alchemy (\$49/месяц) при необходимости полноценной WebSocket функциональности.
3. **Для обогащения данных** использовать бесплатные API с агрессивным кэшированием, с возможностью позже добавить CoinGecko Pro при необходимости.
4. **Разработать архитектуру с учетом возможности переключения между провайдерами**, что обеспечит гибкость и устойчивость системы.
Такой подход позволит вам начать работу с минимальными затратами (потенциально \$0 на старте) и постепенно масштабировать систему, добавляя платные API только по мере необходимости и подтверждения ценности системы.
Да, такие сервисы **есть** — и как раз вокруг них и строится половина современной on-chain аналитики 🧠
Но вот что важно понять:<br>они **обогащают не всё подряд**, а обычно дают либо:
- **агрегированные данные (API-аналитика)** — сигналы, сводки, метрики;
- либо **отфильтрованные “action-level” события** — уже после внутреннего обогащения.
И в 90 % случаев у них:
- нет полного потока (raw blockchain stream),
- а доступ стоит от **\$300–\$2000+ в месяц**,
- и всё равно нужен твой собственный фильтр, если хочешь именно свою “Smart Money” аналитику.

## 🧩 1. Full-stack индексеры / RPC-агрегаторы (дают обогащённые данные)
Эти провайдеры уже делают parsing + enrichment под капотом:
| Сервис | Что умеет | Плюсы | Минусы / Цена |
| --- | --- | --- | --- |
| **Helius (Solana)** | enriched transactions API, decoded events, token metadata, account owners | Всё уже распарсено, JSON готов к сохранению, есть WebSocket | Бесплатно 100 req/сек, платно от \$49–199 в мес |
| **Alchemy (EVM)** | “Enhanced API”: `getAssetTransfers`, `getTokenMetadata`, decoded logs | Хорошо структурировано, поддержка Base/Arbitrum | Free ≈ 30 req/сек, Pro от \$49+ |
| **Moralis** | Multichain API (EVM + Solana), returns tx + token info + USD | Единый API на все сети | Сырые данные \> 10 rps – платно |
| **QuickNode Advanced API** | Token metadata, NFT transfers, DeFi data | Легко подключить, кэшированные цены | Про планы \$49–\$299 |
| **Bitquery Stream API** | Realtime decoded events по DEX/NFT/Swap | WebSocket API, фильтрация по контрактам и кошелькам | 10–20 rps free, дальше \$\$\$ |
👉 Если хочется «получать уже обогащённые события», то:
- для **Solana** — **Helius Enhanced API** = лучший вариант;
- для **EVM** — **Alchemy Enhanced API** или **Bitquery Stream**.

## 🚀 3. Если хочешь прям поток как у тебя — но «готовый»
- **Bitquery Stream API** — реально близко: WS-поток swap-событий по любым DEX; можно фильтровать сеть/токен/кошелёк.<br>*Это то, что ближе всего к твоему Smart Money Radar, но уже «готовое».*
- **Helius Webhook** — можно подписаться на определённые accounts/program id в Solana и получать уже обогащённые tx.
- **Moralis Streams API** — создаёшь фильтр (например, Uniswap Swap на Arbitrum) → они шлют в твой endpoint события с уже декодированными параметрами.
